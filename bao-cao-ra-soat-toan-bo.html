🧹 Báo cáo rà soát toàn bộ CleanBoost

Phiên bản rà soát: v2.7.2 (commit sắp push) · Ngày: 28/10/2026 · Người rà soát: Muse (AI) · Người dùng kiểm chứng cuối: DAU SY MANH trên Windows thật

1. Trả lời thẳng: đã chạy được thật hết các tính năng khác chưa?

Chưa — và báo cáo này không nói dối về chuyện đó. Có 3 mức kiểm chứng khác nhau, và chỉ mức 1 mới được gọi là “chạy thật”:

  • CHẠY THẬT — Đã chạy code thật (không giả lập) trong môi trường kiểm thử: test tự động mở app thật dưới màn hình ảo Xvfb và bấm nút thật, hoặc chạy lệnh CLI thật. Kết quả quan sát được, không phải suy đoán.
  • MOCK / REVIEW — Lệnh chỉ tồn tại trên Windows (DISM, netsh, registry, ipconfig…) nên trên máy kiểm thử Linux nó được chạy với lệnh giả lập (mock) + đọc kỹ code. Logic đúng, nhưng chưa từng chạy trên Windows thật — đây là phần cần anh kiểm chứng.
  • CHƯA CÓ TEST TỰ ĐỘNG — Tính năng nhỏ, logic đơn giản, chỉ được rà bằng mắt. Không có nghĩa là hỏng, mà là chưa có bằng chứng tự động.

Kết quả tổng: 104 test tự động PASS (unit + GUI thật), pyflakes sạch, CLI chạy thật 4 lệnh chỉ đọc. Không còn tính năng nào “bấm mà chết im” được biết tới sau v2.7.1 — mọi lỗi nút bấm giờ đều hiện hộp báo lỗi thay vì im lặng. Nhưng 12 mục Windows-only ở §5 vẫn đang chờ anh chạy thử trên máy thật trước khi được gọi là “chạy thật 100%”.

2. Phương pháp rà soát lần này (28/10/2026)

  • Liệt kê toàn bộ tính năng: quét mọi nút bấm trong ui/app.py (34 handler), mọi lệnh CLI trong main.py (9 lệnh + 4 lệnh con quarantine + 3 lệnh con schedule), và các tính năng nền (single instance, action log, scheduler, monitor, check_env).
  • Đối chiếu test: kiểm tra từng handler có được test nào chạm tới không — phát hiện 20/34 handler chưa có test GUI trực tiếp (phần lớn đã có unit test ở tầng module).
  • Quét tĩnh toàn app: mọi lời gọi subprocess (tìm lời gọi không timeout), mọi lời gọi ctypes Windows (kiểm tra argtypes), mọi constructor giao diện CustomTkinter (kiểm tra tham số không hợp lệ — chính cách này bắt được lỗi dialog v2.7.1).
  • Chạy thật: toàn bộ 104 test dưới Xvfb + CLI status / top / quarantine list / scan --level 1 chạy thật trên máy kiểm thử.
  • Sửa ngay những gì sửa được an toàn: timeout cho pip install + dọn 4 cảnh báo pyflakes (xem §4, v2.7.2). Những gì cần Windows thật thì ghi vào §5, không sửa mù.

5. SẼ SỬA — những gì còn lại, theo thứ tự ưu tiên

Ưu tiên 1 — Cần anh kiểm chứng trên Windows thật (không ai khác làm thay được)

Mỗi mục chỉ cần 1 lần thử, ghi lại “được / không được + ảnh chụp nếu lỗi”. Từ v2.7.1, nếu lỗi thì app sẽ tự hiện hộp báo — chụp hộp đó là đủ để sửa.

  1. Tab Network: đối chiếu số liệu với ipconfig /all (IP, DNS, gateway có khớp không?).
  2. DNS: đổi sang 1.1.1.1 → vào mạng được → bấm Undo → về DNS cũ.
  3. Flush Network: bấm xong, mạng vẫn dùng được, không bị rớt.
  4. Adapter Reset: mạng ngắt rồi tự nối lại trong ~30s.
  5. Deep Reset: chạy xong, khởi động lại máy, mạng hoạt động.
  6. Disk Cleaner mức 2/3: scan thử xem DISM / hibernate / restore point hiện đúng không; xóa thử 1 nhóm rác nhỏ.
  7. Quarantine: cách ly 1 file rác → khôi phục lại được → xóa vĩnh viễn 1 mục.
  8. Startup: disable 1 app không phải hệ thống → khởi động lại máy thấy app đó không tự chạy → enable lại được.
  9. Schedule: schedule install → Task Scheduler có task CleanBoost → schedule remove xóa được.
  10. Monitor: chạy với ngưỡng RAM thấp để thấy cảnh báo hiện ra.
  11. Theme sáng: chuyển theme, kiểm tra chữ trên nút có đọc được không.
  12. Mở app 2 lần cùng lúc: chỉ 1 cửa sổ được chạy.

Ưu tiên 2 — Sẽ bổ sung test tự động (Muse làm, không cần anh)

  • Test GUI thật cho các nút chưa có test GUI: thao tác Quarantine (restore/delete/purge), đổi DNS + Undo, bật/tắt Startup, hộp thoại Adapter/Deep Reset, Diagnostics, Bandwidth Hogs, chuyển theme, Select all. Mục tiêu: từ 20/34 handler có test GUI lên toàn bộ nút chính.
  • Hardening ctypes cho lệnh Windows-only (ntdll NtSetSystemInformation, shell32 SHEmptyRecycleBinW): khai báo argtypes/restype cho đúng chuẩn 64-bit. Chỉ làm sau khi anh xác nhận các lệnh đó đang chạy tốt trên Windows — sửa mù code Windows mà không test được là rủi ro, nên để sau bước kiểm chứng ở trên.

Ưu tiên 3 — Chưa làm, theo lộ trình v3.0 (khi anh ra lệnh)

  • Auto Guard (canh tự động), Duplicate Finder (tìm file trùng), Profiles (cấu hình dọn theo hồ sơ), lịch sử SQLite, tray/toast. Đây là tính năng mới, không phải sửa lỗi.

6. Cách kiểm chứng lại (dành cho người kiểm thử)

  • Toàn bộ test: xvfb-run -a python -m unittest discover -s tests (Linux) hoặc Run-Tests.ps1 (Windows) — kỳ vọng 104 PASS.
  • Kiểm tra code sạch: python -m pyflakes main.py ui/ core/ cleaner/ network/ check_env.py — kỳ vọng không có cảnh báo.
  • CLI chỉ đọc: python main.py status, python main.py top -n 5, python main.py scan --level 1, python main.py quarantine list.
  • Quy tắc đã chốt từ trước và vẫn giữ: xong 1 việc → commit + push ngay rồi mới báo; UI app 100% tiếng Anh; không bypass UAC; thao tác nguy hiểm có cảnh báo đỏ + checkbox; mọi hành động ghi action log.

Cam kết: báo cáo này ghi đúng những gì đã kiểm chứng được và những gì chưa. Nếu anh thử 1 mục ở §5 mà không chạy, gửi ảnh hộp báo lỗi (hoặc mô tả “bấm nút X, màn hình hiện Y”) — tôi sẽ sửa đúng chỗ đó và cập nhật bảng này.
