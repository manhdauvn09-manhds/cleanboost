v2.5.1 — Quarantine Destroy

2026-10-19 — Fix silent Quarantine delete failures + Destroy All
Bug fixDelete permanently no longer fails silently.

Two real causes were found: (1) the UI threw away each delete result (ok, _ = ...) and refreshed with no message, so failed items just reappeared with zero explanation; (2) on Windows, shutil.rmtree / os.remove raise PermissionError on read-only files — and quarantined junk often contains read-only files — so those items could never be deleted. Deletes now clear the read-only flag and retry, and every failure is shown with its real OS error. "Clean items over 14 days" also never touched recent items by design — the dialog now says so.

Feature"Destroy All" button on the Quarantine tab (Q.delete_all()).

One click empties the whole quarantine: red warning dialog + "I understand" checkbox required before running, background thread under the busy-guard, every action logged. Result dialog reports deleted count, freed GB, and any items that failed (e.g. locked/in-use files) with their reason — failed items stay listed instead of vanishing silently. Clicking Delete/Restore with nothing selected now says "No item selected" instead of doing nothing.

v2.5 — "Smart"

2026-10-19 — DNS Switcher, Diagnostics, Hog Finder, Startup Manager, Adapter/Deep Reset
FeatureDNS Switcher (network/dns.py) on the Network tab.

Switch to Cloudflare / Google / Quad9 or back to Auto (ISP) in one click. The current DNS is always saved to dns_backup.json before any change, so Undo restores exactly what was there. "Measure fastest DNS" resolves via each provider on this PC (nslookup) and suggests the fastest. Changing DNS needs Admin and says so clearly when it is missing.

FeatureNetwork Diagnostics (network/diag.py) — one click, auto conclusion.

Checks gateway ping, external pings (1.1.1.1 / 8.8.8.8), DNS resolve time, established connections + top remote IPs, and WiFi signal — then concludes by exclusion: WiFi/LAN problem, ISP/route problem (try Quick Refresh), slow DNS (try DNS Switcher), or network fine (lag is from the app/server).

FeatureBandwidth Hog Finder (network/hogs.py).

Measures real total up/down throughput (two net_io_counters snapshots) and lists apps by active connection count, with End task per app through the protection layer. Honest limit, stated in the UI: psutil cannot attribute bytes to individual processes, so rows are ranked by connections, not per-app bytes.

FeatureStartup Manager (core/startup.py) — new "Startup" tab.

Lists HKCU/HKLM Run entries plus both Startup folders. Disabling NEVER deletes: the entry is renamed with the CleanBoost_disabled_ prefix and one click re-enables it. Protected entries (Windows Security, audio/network drivers) cannot be disabled. HKLM changes need Admin.

FeatureAdapter Reset + Deep Reset (network/refresh.py).

Adapter Reset: 3-second countdown dialog with Cancel, then Disable → wait 3s → Enable, verified for up to 30s. Deep Reset: red warning + "I understand" checkbox required before running netsh winsock reset + netsh int ip reset, with a clear "restart your PC" message. Both need Admin and log every step.

NoteWindows-only behaviour verified on real Windows only.

The dev machine is Linux, so netsh / registry / Disable-NetAdapter paths could only be checked with mocked unit tests here. Real verification checklist: change DNS then Undo back to the exact old DNS; disable a startup app then re-enable it; Adapter Reset reconnects WiFi within 30s.

v2.4 — "Fresh Network"

2026-10-19 — Network tab, Health Score, Optimize in 1 Click
FeatureNew "Network" tab: Network Info Dashboard.

Shows Local IP, Subnet, MAC, Global IP, Gateway, DNS and WiFi (SSID, signal %, link rate) without typing ipconfig. Read-only, no admin needed. Global IP uses api.ipify.org with an ifconfig.me fallback (5s timeout). Gateway/DNS parse ipconfig with route print / netsh fallbacks because ipconfig output depends on Windows display language.

FeatureNew "Network" tab: Port & SSH Inspector.

Lists every LISTEN port with the process holding it and its scope (LAN / Local only). Port 22 gets its own status line (OPEN with process name, or closed — safe). Sensitive ports (21 FTP, 23 Telnet, 445 SMB, 3306 MySQL, 3389 Remote Desktop, 5432 PostgreSQL, 5900 VNC) bound to 0.0.0.0 get a red flag; the "How to close" button explains how to close each one. safety/protected.py now holds SENSITIVE_PORTS + port_severity().

FeatureNew "Network" tab: Speed Test before/after + Quick Refresh.

First test is saved as Before; run again after Quick Refresh to compare (ping delta shown). Quick Refresh runs ipconfig /flushdns → /release → /renew in a background thread with per-step progress, logs every step to action_log, then pings the gateway to verify the connection is back. No third-party libraries: ping via subprocess, DNS time via nslookup (socket fallback), download speed via a 10 MB Cloudflare test file.

FeatureHealth Score 0–100 on the Overview tab (core/health.py).

One number from a transparent formula: RAM free × 0.3, disk free × 0.3, junk / 5 GB (max 20), startup apps / 20 (max 10), days since last clean / 30 (max 10). The breakdown and a concrete suggestion are shown under the score. Startup count is a read-only registry count; days-since-clean comes from the clean entries in action_log. The score never scans the disk itself — the UI passes the level-1 scan total.

Feature"Optimize in 1 Click" button (core/optimize.py).

Runs the safe chain only: Light RAM clean (kills nothing) → level-1 junk of default_on groups to quarantine (never permanent delete — permanent deletes still need per-group confirmation in Disk Cleaner) → Quick Refresh. Reports RAM %, quarantined GB, and ping before/after, with an overall progress bar. All steps run in a background thread under the busy-guard.

UXAll new UI strings are English; version label bumped to v2.4.

Vietnamese text had font rendering problems in the UI (v2.3 rule), so the Network tab, Health Score and Optimize UI are English-only.

NoteWindows-only behaviour verified on real Windows only.

The dev machine is Linux, so ipconfig / netsh / ping -n paths could only be checked with mocked unit tests here. Real verification checklist for the user: numbers match ipconfig /all, Quick Refresh reconnects, Port Inspector reports port 22 correctly when OpenSSH Server is toggled.

v2.3 PRO

2026-10-10 — Stability, security & English UI
UXProgress + no double-click on every task.

Clicking a button twice used to start two background threads that could fight over the UI and hang the app. Now a global busy-guard disables a task's buttons while it runs (RAM clean, emergency, process refresh/kill, scan, clean, quarantine restore/delete/purge) and re-enables them when done. The status bar shows what is running.

SecurityProtected-path check now resolves symlinks.

A path like C:\link pointing at C:\Windows\System32 could previously slip past the protected-path check. is_protected_path() now uses realpath so symlink tricks can never reach system folders.

SecurityQuarantine restore/delete hardened against path traversal.

The quarantine index (index.json) is local data that could be tampered with. A crafted stored value like ../../.. could make restore/delete touch files outside quarantine. All three operations now verify the resolved path stays inside the quarantine root.

SecuritySingle-instance kill is immune to PID reuse.

The lock file stored only a PID. If the old instance exited and the OS reused that PID for another process, "close old instance" could kill an innocent process. The lock now stores the process creation time too, and the PID is only killed when the creation time matches.

Bug fixDeep-drive scans can no longer blow up RAM.

scan_rule() collected every matched path into two full in-memory lists with no cap — a whole-drive pattern scan could consume gigabytes and freeze the app. Scanning is now streaming (no intermediate full list) and the collected path list is capped at 200,000 per rule; the UI notes when the cap is hit.

FeatureSelf-healing launchers — no more re-running setup after git pull.

Previously, pulling new code with new dependencies (e.g. Pillow) required manually re-running setup_windows.bat. New check_env.py hashes requirements.txt and auto-installs on change; every launcher (run_cleanboost.bat, admin, CLI) and git_pull.bat calls it. First-time setup still needs setup_windows.bat once.

UXEntire app switched to English.

Vietnamese text had font rendering problems in the UI. All GUI strings, CLI output, rule names/impacts/notes/warnings, dialogs, batch files and the manual are now in clear English. New manual: USER_MANUAL.md (the Help ? button reads it).

FeatureThis changelog (history.html).

Every fix/change from now on is recorded here with what was done and why, so nothing gets lost between versions.
